# 提示词优化（@local/dsh-prompt-polisher）

在对话输入框左侧加一个 ✦ 按钮：点一下，把当前草稿改写成可直接发出去的 Prompt；先看差异，再决定是否替换输入框。输入框内容不会在你点「替换输入框」之前被改动。

两种模式：

- **结合当前对话**（默认）：Host 读取当前会话这一分支可见的最近几轮用户消息和助手回复，把「按第二种来」「刚才说的那块」这类指代解析成具体任务，只给一个推荐稿。
- **快速改写**：只看草稿本身，给出结构化 / 任务单 / 精简三个版本。

## 用法

1. 在输入框写下想做的事（至少 4 个字符），点 ✦。
2. 小窗顶部会显示这一轮实际参考了什么：`已参考最近 N 轮`、`当前仅依据草稿`，或 `会话不可读取，已退回纯草稿`。
3. 「结合当前对话」模式输出一个推荐稿；「快速改写」给出三个版本：
   - **结构化**：目标 / 上下文 / 要求 / 交付，信息最全；
   - **任务单**：任务 / 背景 / 范围 / 约束 / 验收，适合复杂任务；
   - **精简**：只留目标和关键约束。
4. 「差异」显示相对原稿的增删，「全文」显示完整结果。
5. 点「替换输入框」写入当前版本；点「复制」只复制不改输入框；发送仍由你自己按回车。
6. 勾选「停顿后快速改写」后，停止输入约 1.2 秒会自动用快速模式改写一次（记住上次选择）。自动模式只发草稿，不读会话。

改写只补结构，不替你编事实：缺失且影响执行的信息会写成 `[文件夹路径]`、`[验收标准]` 这类占位符。专有名词、路径、命令、数字保持原样。指代实在定不下来时，只加一条「待确认：……」而不是硬猜。

结果和请求绑定：草稿、会话或模式一变，旧结果会标成旧版本，且「替换输入框」不可点；切换会话会中止还没回来的请求。晚到的旧响应不会覆盖新结果。

## 结构

- `index.js`（Host 半）：注册 `POST /dsh-prompt-polisher/rewrite` 和 `GET /dsh-prompt-polisher/health`。`rewrite` 用 `ctx.get('sessions').get(sessionId)` 读当前会话 `surface.nodes` 对应的 `snapshotEvents()`，只取 `source.kind === 'user'` 的用户消息和紧随其后的助手文本（最近 4 轮、单条 2400 字符、总计 7000 字符）；再用 `ctx.llm.stream()` 生成结果。
- `client.js`（Web 半）：通过 `ctx.slots.inject('conversation.input.left', ...)` 挂按钮和小窗；用 `props.inputActions.setDraft()` + `persistDraft()` 写回输入框。
- `cordis.patch.yml`、`package.json`：bundle 声明；`locale/*.json` 提供插件市场里的标题和描述。

## 已知边界

- 改写使用当前会话选中的模型和推理等级（默认跟随输入框里的选择；未设置时用 high），输出 token 上限交给模型适配层，不额外截断。
- 单次请求超时 180 秒，草稿上限 12000 字符。
- 会话 id 来自浏览器端，Host 只把它当定位符：能读到就参考，读不到就退回纯草稿，不做额外鉴权。
- 参考范围是当前分支可见的文本消息，不含工具调用、附件内容和被回滚掉的轮次。
- 小窗以输入框卡片为定位基准贴在卡片上方（宽度随卡片缩放 240–560 px，顶部留 44 px 安全区），上方空间不足时翻到卡片下方；右侧边栏展开时也不会被裁掉。
- 只处理文本，不带附件、不读文件内容。
